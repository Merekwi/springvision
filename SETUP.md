# SpringVision — подключение настоящего backend

## Текущее состояние

- Интерфейс и 271 локальный SVG-флаг в форме сердца находятся в GitHub.
- Есть миграция базы и Edge Function `api`, которая проверяет подпись Telegram Mini App `initData`.
- Настоящая отправка заявок включается только после подключения отдельного активного Supabase-проекта и секретов сервера.
- Не используйте проект Supabase `rbn` для SpringVision: это существующий проект другого сайта, и сейчас он недоступен/неактивен.

## 1. Создайте отдельный Supabase-проект

Создайте проект SpringVision в своём Supabase-аккаунте. Перед созданием проверьте тариф и лимиты; не включайте платные ресурсы. После создания сохраните **Project URL**, **publishable/anon key** и **Project ref**.

## 2. Примените миграцию

Установите Supabase CLI, войдите и выполните в корне репозитория:

```bash
supabase login
supabase link --project-ref YOUR_SPRINGVISION_PROJECT_REF
supabase db push
```

Миграция `supabase/migrations/20261024000000_springvision_core.sql` создаёт таблицы сезонов, профилей, стран, заявок, ролей жюри, голосов, уведомлений, журнал аудита и закрытое хранилище `springvision-private`. Она закрывает прямую запись из браузера через RLS; изменения должны идти через Edge Function.

## 3. Задайте серверные секреты

Получите токен бота у @BotFather и свой **числовой Telegram ID**. Затем задайте секреты в командной строке (значения не добавляйте в Git):

```bash
supabase secrets set TELEGRAM_BOT_TOKEN="TOKEN_FROM_BOTFATHER"
supabase secrets set SPRINGVISION_OWNER_TELEGRAM_ID="YOUR_NUMERIC_TELEGRAM_ID"
```

Supabase предоставляет Edge Functions переменные `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY`. Никогда не копируйте `service_role` или токен Telegram в `config.js`, HTML, JavaScript клиента или публичные GitHub Secrets.

## 4. Разверните Edge Function

```bash
supabase functions deploy api
```

Функция проверяет подпись и свежесть Telegram `initData` на сервере. Она использует `SPRINGVISION_OWNER_TELEGRAM_ID` для выдачи роли главного администратора; username не используется как защита.

## 4.1. Напоминания жюри по расписанию

Создайте длинный случайный секрет и задайте его в Supabase:

```bash
supabase secrets set SPRINGVISION_CRON_SECRET="LONG_RANDOM_SECRET"
```

В GitHub откройте **Settings → Secrets and variables → Actions** и добавьте secrets:
- `SPRINGVISION_SUPABASE_URL` — URL нового SpringVision Supabase-проекта.
- `SPRINGVISION_SUPABASE_ANON_KEY` — его публичный publishable/anon key.
- `SPRINGVISION_CRON_SECRET` — то же значение, что в Supabase.

Workflow `.github/workflows/jury-reminders.yml` запускается каждые два часа. До дедлайна он напоминает жюри, которое ещё не проголосовало. После дедлайна закрывает голосование жюри и создаёт резервные случайные бюллетени только тем, у кого нет сохранённого голоса. Сначала протестируйте расписание на отдельном тестовом сезоне.

## 5. Подключите frontend

Откройте `config.js` и укажите публичные данные **именно нового SpringVision-проекта**:

```js
window.SPRINGVISION_CONFIG = {
  supabaseUrl: "https://YOUR_PROJECT_REF.supabase.co",
  supabaseAnonKey: "YOUR_PUBLISHABLE_OR_ANON_KEY",
  demoMode: false
};
```

Это единственные ключи Supabase, которые допустимы в клиентском файле. После изменения сохраните файл в GitHub.

## 6. Опубликуйте сайт

В настройках репозитория откройте **Settings → Pages** и выберите публикацию из ветки `main`, папка `/(root)`. URL сайта укажите в @BotFather как Web App URL. Убедитесь, что Telegram Mini App открывается именно по HTTPS.

## Что уже покрывает API

- Проверка Telegram `initData` и создание профиля по числовому Telegram ID.
- Заявка с загрузкой рекап-файла до 50 МБ в приватное хранилище; уникальная активная заявка на страну и пользователя в сезоне.
- Список сезона, занятые страны, публикация участников и подписанные временные ссылки на рекапы для допущенных зрителей/жюри.
- Создание сезона, список заявок, одобрение/отклонение с комментарием, выдача сезонного права жюри, жеребьёвка, ручные флаги публикации.
- Голос жюри и телеголосование с проверкой набора баллов 12, 10, 8–1, запретом повторов и запретом голосовать за свою заявку.
- Назначение администраторов главным администратором, отправка уведомлений, загрузка записи финала, выдача ссылок на скачивание рекапов.

## Что ещё нужно завершить перед публичным запуском

1. Подключить активный проект Supabase и выполнить миграцию — сейчас миграция не применена к базе.
2. Закончить полноценные экраны админ-панели, жюри и телеголосования на frontend.
3. Протестировать скачивание рекапов ZIP, напоминания жюри каждые два часа и генерацию случайных голосов только для пропустивших дедлайн.
4. Протестировать все сценарии на тестовом сезоне, проверить RLS, ограничения Storage и уведомления.
5. Включить GitHub Pages и настроить Web App URL в BotFather.

До выполнения этих шагов не считайте сайт готовым к реальному сезону: деморежим специально не выдаёт ложного подтверждения сохранения данных.
